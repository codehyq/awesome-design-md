# Clear Ledger / 清账

> 让每一笔，都清清楚楚。

这是一套个人记账 App 的浅色设计系统。适合记录日常收支、快速查账、查看预算和月度分类统计。它优先解决“记得快、找得到、看得明白”，不使用投资交易终端的信息密度，也不依赖大面积插画建立识别度。

可操作样例：[应用演示](demo.html) · [组件预览](preview.html)。代码 token 见 [tokens.css](tokens.css)，示例业务口径见 [model.js](model.js)。演示使用虚构数据和浏览器本地存储。

## 1. Visual Theme & Atmosphere / 视觉主题

三个关键词：清晰、平静、有秩序。

- 用近白灰底分离页面与白色内容面板。大部分流水直接放在画布上，只有收支概览、预算、图表需要卡片。
- 蓝色只强调主操作、选中项、预算进度和趋势线。不要把每一块内容都涂成蓝色。
- 记账行为是主角。首页先回答本月结余、收支和预算，再展示最近账单。
- 大数字靠字号和字重建立层级，普通说明保持低调。正文用自然中文，不在 App 内堆放英文装饰标题。
- 单色细线图标搭配低饱和分类底色。分类图标有可见的中文标签。

风格辨识来自数字排版、留白节奏和轻量分隔线；换成其他强调色时，这些结构仍应保持。

## 3. Typography Rules / 字体与金额

字体顺序为 Inter、系统西文字体、PingFang SC、Microsoft YaHei、sans-serif。演示不下载外部字体；没有安装 Inter 时使用系统回退字体，不依赖品牌专有字体。

| 角色 | 字号 | 字重 | 行高或要求 |
| --- | --- | --- | --- |
| 首页结余 | 38px | 650 | 1.3，字距 -1.5px |
| 金额输入 | 40px | 600 | 1.3，字距 -1.3px |
| 统计总额 | 27px | 650 | 随金额长度允许换行 |
| 页面标题 | 23px | 700 | 字距 -0.7px |
| 收入／支出小计 | 18px | 650 | 两列分别对齐 |
| 分区标题 | 15px | 650 | 不使用全大写中文标题 |
| 流水金额 | 14px | 600 | 靠右对齐 |
| 流水主描述／正文 | 13px | 400–550 | 说明文字至少 1.6 倍行高 |
| 日期、账户、图例 | 10–11px | 400 | 仅用于短辅助信息，不承担主要操作说明 |

金额使用 font-variant-numeric: tabular-nums。演示的单币种为人民币，固定显示两位小数，千位分隔；主要金额带 ¥，流水通过页面语境明确单位。列表超长备注单行省略，详情中显示完整内容；金额不能省略成含糊的“9.9k”。窄屏允许长金额断行，不压住备注或按钮。

## 4. Component Stylings / 组件与状态

### 主按钮与选择

主按钮最小高度 48px，圆角 12px，蓝底白字；悬停使用 --primary-hover。每个区域只保留一个主操作。保存按钮显示“保存这笔支出／收入”，避免不明确的“确定”。

次按钮用白底和细边框。禁用态降低透明度，同时使用 disabled 语义；键盘焦点为 3px 蓝色外框，偏移 3px。收入／支出分段选择器使用浅灰容器、白色选中块；分类选中态同时具有蓝色底、蓝色边框和 aria-pressed。

### 收支概览卡

圆角 20px，1px 分隔色边框，内边距约 22px。顺序固定为“本月结余 → 大金额 → 分隔线 → 收入与支出”。结余是当月收入减当月支出，不能标为账户总余额。收入、支出的小标签配方向图标。

### 预算卡

圆角 16px，内边距 16px 18px。展示预算总额、5px 进度条、剩余可支出金额和使用比例。超过预算时进度条填满，文字改为“已超预算”，展示超出额；百分比允许超过 100%，不能暗中截断成 100%。预算编辑不改变账单。

### 流水行

最小高度 68px，左侧 39px 分类图标，12px 间隔，主文案优先用备注，副文案为分类和账户；金额右对齐。整行可点击，读屏标签包含类型和金额。按日期分组，每组展示日期、星期和当天支出汇总。最后一行无需额外分隔线。

### 输入与表单

金额为大字号文本输入，设置 inputmode=decimal，保留输入字符串直至提交，不在用户输入中途强制重排。金额、日期、账户均有可见标签。备注最多 80 字符。输入错误在保存区域之前显示，使用 role=alert、aria-invalid 与焦点定位；用户输入内容保留。

分类图标四列排列；每项至少 76px 高。账户、日期、备注使用清晰的横向表单行，控件最小高度 44px。保存按钮跟随表单位于可滚动区域末尾；软键盘或矮屏不得遮挡保存入口。

### 底部导航与弹窗

四项为总览、账单、记一笔、统计；导航项至少 52px 高。选中态有颜色和 aria-current。记一笔使用蓝色加号底块，但不夸张悬浮。导航下方考虑系统安全区域。

账单详情、预算和关于使用原生 dialog。打开时焦点进入弹窗，Escape 可关闭，提供可见关闭按钮。危险操作先展示删除入口，再明确确认。不可把无关设置放进主记账流程。

### 图表

支出累计用单条蓝色折线和淡色面积，下方标注日期。分类统计用环形图和排序列表。数据来自相同账单集合，不使用装饰性假曲线。图表有文字说明，分类金额与占比可在列表中读取。

## 5. Layout Principles / 布局与页面

以 390×844 为参考，主体内容左右 24px；360px 窄屏改为 20px。间距基于 4px，常用 8、12、16、20、24、32px。模块之间比模块内部留出更多空间。

| 页面 | 信息顺序 | 首要操作 |
| --- | --- | --- |
| 总览 | 标题 → 月份 → 收支概览 → 预算 → 记账 → 最近流水 | 记一笔 |
| 账单 | 月份 → 收支小计 → 搜索 → 类型筛选 → 日期分组 | 搜索或查看详情 |
| 记一笔 | 收支切换 → 金额 → 分类 → 账户／日期／备注 → 保存 | 保存当前账单 |
| 统计 | 月份 → 支出累计 → 分类占比 → 分类金额排行 | 切换月份理解支出 |

页面中部独立滚动，页头和底部导航留在应用边界内。不要把整页都塞进一个无法滚动的手机截图。空状态应替换缺失的数据区域，保留页面导航与月份切换。

## 6. Depth & Elevation / 层级与动效

| 层级 | 表现 | 使用位置 |
| --- | --- | --- |
| 0 | 灰白画布，无阴影 | 页面、流水列表 |
| 1 | 白色表面、1px 轻边框、极轻投影 | 收支和图表卡片 |
| 2 | 蓝色底或蓝色浅底 | 主操作、当前选择 |
| 3 | 深色半透明遮罩、浮层投影 | 对话框和 Toast |

卡片投影为 0 4px 20px #19233805；浮层为 0 12px 36px #19233818。演示页外部的手机壳投影只是展示框，不属于 App 的组件 token。

本版不依赖动画建立层级。后续过渡控制在 120–180ms，只用于状态反馈；尊重 prefers-reduced-motion，不用持续发光、跳动或自动轮播。

## 7. Do's and Don'ts / 设计边界

应该做：

- 同一金额在概览、账单、详情、统计中保持一致。
- 有限使用品牌蓝，让“记一笔”和“保存”容易发现。
- 保持数字列对齐，使用明确的收入／支出标识。
- 在详情显示完整备注、账户和日期。
- 为无账单、无支出、超预算、错误金额和存储失败提供可见反馈。
- 新页面优先复用 tokens.css 和现有组件，再补充必要规则。

不要做：

- 用大面积渐变、玻璃效果或漂浮装饰遮盖核心数据。
- 把日常支出全部标红，暗示每次消费都是错误。
- 用大于 40px 的营销标题挤占手机首屏。
- 把结余混同资产余额，把转账混同收入和支出。
- 因为数字太长就截断金额，或只提供颜色而没有文字。
- 展示看起来可点击却没有行为的按钮。
- 把浏览器演示称为正式财务系统或已实现云同步。

## 8. Responsive Behavior & Accessibility / 响应式与可访问性

| 可用宽度 | 行为 |
| --- | --- |
| 360–370px | 左右边距 20px，结余字号 34px，收入／支出字号 16px |
| 371–600px | 使用全宽 App，无装饰性手机壳；考虑 100dvh 与底部安全区域 |
| 601–740px | 居中显示手机预览，隐藏侧边介绍，避免水平溢出 |
| 741–850px | 展示页左右介绍和手机预览并排，缩小外部留白 |
| 851px 以上 | 展示页居中排列介绍与手机，App 内容宽 390px，不扩成桌面金融仪表盘 |

所有交互目标最小 44×44px；文字小按钮可以保留小字号，但不能缩小可点击区域。移动端操作优先触控；键盘用户能访问全部导航、表单、弹窗和下载链接。浏览器字体放大后允许垂直滚动和内容换行。

图表提供语义标签；错误消息可被读屏发现；背景与文本采用明确的对比色。金额区域不要把币种符号和金额拆到没有上下文的两个区域。嵌入目录的小预览不可操作，外部提供清晰的“体验 App”链接。

## 9. Agent Prompt Guide / 交给 AI 的提示

将本文件加入项目，并在 AGENTS.md 指明路径；Markdown 文件不会因为命名为 DESIGN.md 就在所有工具中自动生效。

```text
请先阅读 design-md/ledger-clean/DESIGN.md，并把它作为本项目的视觉规范。
实现一个中文移动端个人记账 App，先完成总览、账单、记一笔、统计。
复用文档的颜色角色、数字排版、间距、组件状态和移动端布局。
金额采用明确的业务计算规则，所有页面从同一数据来源计算汇总。
不要增加营销区、大面积渐变、装饰卡片或没有行为的按钮。
请检查空状态、长金额、长备注、错误输入、超预算和小屏布局。
业务需求与本规范冲突时，先说明冲突并提出具体处理方案。
```

扩展账户页面时继续使用同一视觉语言；先定义账户余额、转账和退款规则，再设计相应交互，不能仅凭当前四页演示推断完整业务。

## 10. Demo Contract & Known Gaps / 演示口径与限制

- 初始月份为 2026 年 10 月，数据为虚构账本；另有九月示例用于月份切换。
- 金额以整数分存储和汇总；输入最多两位小数，大于 0，单笔上限 9,999,999.99 元。
- 支持新增收入／支出、查看详情、确认删除、调整预算、搜索与月份切换；不包含编辑既有账单。
- 浏览器 localStorage 保存当前演示记录，重置会恢复初始数据；存储失败时明确说明改动只存在当前页内存。
- 不包含登录、服务端持久化、云同步、备份、多币种、完整账户余额、转账、退款或真实财务控制。
- 本版只定义浅色模式。暗色需要重新设计表面层级和语义色，不能只反转颜色。
- 小字号辅助信息适合紧凑账本；面向低视力或长辈用户的衍生产品应提升正文与元数据字号，并重新检查布局。
- 参考 Wise、Linear、Revolut 的规范组织方式与设计分析深度；页面、配色与代码为本条目的场景设计，没有使用其商标、图片或专有字体。
